## 4-Stage Quality Gate

품질을 한 번에 검증하지 않고, 개발 흐름의 각 지점마다 점진적으로 검증합니다.

```
[1. 코드 작성] → [2. PR 생성] → [3. 머지 후] → [4. Sprint 종료]
   로컬 검증       자동 검증      통합 환경 검증    수동 데모 검증
```

---

## 단계별 상세 기준

### 1단계 — 로컬 검증 (코드 작성 후)

커밋 전 pre-commit 훅이 자동 실행됩니다.

| 검사 항목 | 도구 | 기준 |
|---|---|---|
| 코드 포맷 | `black` | 포맷 오류 0건 |
| import 정렬 | `isort` | 정렬 오류 0건 |
| 코드 품질 | `flake8` | 경고 0건 |
| 민감 정보 | `detect-private-key` | 감지 0건 |

### 2단계 — 자동 검증 (PR 생성 시)

GitHub Actions CI가 자동 실행됩니다.

| 검사 항목 | 도구 | 기준 |
|---|---|---|
| 린트 전체 | `black`, `isort`, `flake8` | 모두 통과 |
| 단위 테스트 | `python manage.py test` | 실패 0건 |

### 3단계 — 통합 환경 검증 (develop 머지 후)

| 검사 항목 | 기준 |
|---|---|
| API 응답 정상 여부 | 주요 엔드포인트 200 응답 확인 |
| 프론트엔드 연동 | React에서 API 호출 정상 동작 |
| 외부 API 연동 | Map API, 서점 API 정상 응답 |

### 4단계 — 수동 데모 검증 (Sprint 종료)

| 검사 항목 | 기준 |
|---|---|
| 기능 시연 | Sprint 목표 기능 전체 동작 확인 |
| UI/UX 검토 | 팀 전체 합의 |
| 버그 리포트 | 발견된 버그 다음 Sprint 이슈 등록 |

---

## PR 머지 조건

- [ ] CI 모든 단계 통과
- [ ] 팀원 1명 이상 코드 리뷰 승인
- [ ] 관련 테스트 코드 포함
